# 品質ゲート相互補完で判明した応答契約の欠落

| 項目 | 内容 |
|---|---|
| トラック | B（C から昇格。既存応答の文書化のみ） |
| 状態 | done |
| 目的 | F# / Java の実応答を共通 OpenAPI に厳密照合できるようにする |
| 業務・製品挙動 | 変更しない |

## 発見

OpenAPI の operation responses に認証・認可・転送層の応答が記載されていない。
既存の認可マトリクスは401/403を期待するが、契約検証器は未記載ステータスを黙認していた。
その黙認を除去する計画と「OpenAPI 差分ゼロ」は両立しない。

## 変更案

- 保護対象 operation に401/403と共通 ProblemDetails を記載する。
- レート制限対象に429、既存 body guard 対象に413/415を記載する。
- 外部価格照会など、既存テストで期待する他の応答も、その operation に限定して記載する。
- 未定義 method の405や未知 path の404は、新しい operation を作らず HTTP セマンティクステストで検証する。
- 成功応答・入力・状態・権限・計算・製品コードは変更しない。生成物は契約から再生成する。
